# 0.4.2 — resolve project hooks without PATH

Project setup now records the actual Scrip runtime in the documented hook command.
Previously, the hook used a bare `scrip` command. An agent host with an older PATH could
fail to launch it even while a newly opened terminal could run `scrip start`.

After installing this release, run `scrip setup --apply` once in an existing configured
project, followed by `scrip start`. Begin a new agent turn to load the updated hook.
Native permission rules still apply. Project status reports the last actual hook callback
and its conversation binding; successful setup alone does not establish live delivery.

Bundled-executable checks now remove Scrip from PATH before invoking generated hooks.
The installer remains unsigned while provider review is pending.
