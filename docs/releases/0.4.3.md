# 0.4.3 — Windows hook command transport

Antigravity 2.32.1 loaded the project hook but failed to launch its quoted executable path.
The previous native smoke check added its own CMD quoting, which hid this failure.

Windows setup now generates an encoded Windows PowerShell invocation. It passes the hook
JSON to Scrip using UTF-8, retains the executable's exit status, and resolves Scrip's runtime
directly. Paths containing spaces, apostrophes, and shell characters stay inside the encoded
script. Native checks pass the generated command through the argument-list boundary that
reproduced the observed failure and use non-ASCII project paths and JSON input.

After updating, run `scrip setup --apply` and `scrip start` in the project, then request a
shell command in a new agent turn. Check `scrip status --project` for actual hook delivery.
Live automatic approval still requires confirmation from the host. Installer signing is
pending provider approval.
