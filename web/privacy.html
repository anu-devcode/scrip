PRIVACY

Your project stays
on your computer.

Scrip Terminal uses local state for project configuration, command authorization, and decision history. No Scrip account is required.

Local application data

The terminal app stores workspace paths, authorized commands, conversation identifiers, tool arguments, decisions, and event history under your Windows user profile. This material can contain private information. Scrip has no application telemetry or cloud sync.

The terminal approval workflow reads and writes its local SQLite state directly. It does not need the older desktop app’s loopback service or send agent events to this website.

The last-callback diagnostic records processing stage, exception type, field names/types, and response category. It excludes raw command values, transcript content, and exception messages. The event database can still contain command arguments; treat it as private.

Project settings

Only explicit scrip setup --apply writes the project hook configuration. It preserves unrelated hooks and backs up existing contents. Start and stop change private authorization state rather than application binaries or global IDE settings.

This website

The site provides product pages and downloadable files. It has no analytics scripts, advertising trackers, sign-up forms, or application cookies. Copy buttons use your browser clipboard only when clicked.

Hosting infrastructure processes connection information such as IP addresses and request metadata to serve the website and downloads. Your agent and third-party services have their own data practices.

Stopping and removing data

Use scrip stop to revoke future Scrip approvals in a configured project. Remove the Scrip project hook before uninstalling. Private state remains after uninstall to preserve history; back it up before deleting it manually.

Do not publish local databases, setup records, tokens, or unredacted agent transcripts.
