SECURITY & PERMISSIONS

A clear go-ahead.
With clear limits.

Understand the scope you authorize before starting a conversation. Scrip uses documented hooks and preserves the agent’s native controls.

What start authorizes

scrip start authorizes all shell commands in one conversation for the configured project. The first valid callback binds the conversation. Authorization expires after 24 hours or is revoked by scrip stop.

This includes commands that write or delete files, publish software, access the network, or use credentials already available to the agent. A working directory is not a sandbox and does not limit what a shell command can access. Use session mode only when that scope matches your intent.

What remains in your hands

Native Ask and Deny rules still apply. Other conversations and projects do not inherit the grant. Questions are never answered by command authorization. MCP, browser, and other tool types are outside this hook’s command scope.

Stop prevents future Scrip approvals. It cannot cancel running commands, undo completed changes, or recall a decision already returned. Error cases still request native review.

How it connects

One-time setup modifies only the project’s documented hook file after explicit approval. Scrip does not patch vendor files, poll internal IDE commands, or click approval dialogs. The local state is not a security boundary against another process running as your OS user.

Download integrity

The current Windows installer is unsigned. Published SHA-256 checksums help detect a changed download but are not signed provenance. Download from this domain and check the release metadata. Publisher signing remains outstanding.

Release assurance

Checks cover conversation isolation, concurrent binding, stop, expiry, deny precedence, replay, and callback validation. Native packaging checks invoke the bundled executable through cmd and PowerShell using inert command strings. Live host-version certification is incomplete.

A dedicated private vulnerability disclosure channel is not yet available. Do not submit secrets or exploit details through public channels. Assess this limitation before deploying Scrip in a sensitive environment.
