Running the Scrip command in an editor’s terminal doesn’t mean Scrip can control that editor’s agent. Each agent requires its own documented integration.

Find the next step.

PowerShell 
scrip status --project
“Scrip is not recognized”

Restart the editor or terminal’s parent app after installation. Confirm the installer’s user-PATH option was selected. The installed executable is %LOCALAPPDATA%\Programs\ScripTerminal\scrip.exe.

Active, but no conversation is bound

Start from the intended project root, then ask the agent to run a shell command in that project. Until a valid hook callback arrives, Scrip cannot bind the conversation. Active status is local authorization, not proof of host delivery.

The agent still asks with Turbo selected

Native Ask/Deny rules and other enabled hooks can override a permissive preset. Review project-level rules and enabled hooks in Antigravity. Scrip does not remove those controls or approve an already-open prompt.

“Scrip unavailable”

The hook failed before a decision completed. Status includes a last-callback diagnostic with processing stage and field types. Version 0.4.0 fixes the observed top-level cwd callback format. Error cases still require native review.

The wrong conversation got bound

Run scrip stop, then scrip start. Continue only the intended conversation until its first valid shell-command callback arrives. Another conversation won’t inherit that binding.

Approval expired or I switched projects

Authorization expires after 24 hours. Run start from the configured project root. Each project has separate authorization; a parent folder or another project is not the same scope.

How do I report an issue?

Collect the Scrip version, OS, host version, and diagnostic stage/error type. Redact project paths, conversation identifiers, and private information before sharing. Keep databases, access tokens, and raw agent transcripts private. A dedicated public issue tracker and private disclosure inbox are not yet available.

What this release doesn’t promise.

No universal IDE compatibility, automatic question answers, MCP/browser approval, remote control, token optimization, or product deployment automation. Native host-version certification is still in progress. Protocol and bundled-executable checks establish specific behavior; they do not prove every live agent version works.
